# DECISIONS

## 1. Вся обработка продаж собрана в SalesAnalyticsService и не меняет исходный список
Сервис получает List<Sale> и возвращает новые коллекции: List через collect, Map через groupingBy с TreeMap, Optional через min. Внутри stream нет обращений к внешним коллекциям, поэтому побочных эффектов нет, а SelfCheck проверяет, что исходный список после всех операций остался прежним. Проверка списка на null и на null-элементы вынесена в один private метод checkSales, и каждый публичный метод вызывает его первой строкой.

## 2. Параметр варианта вынесен в SalesRules
Вариант 6, дополнительный агрегат, значение 35: количество продаж по регионам, в которых сумма не меньше 35 (ровно 35 входит, 34.99 нет). Число хранится в одной константе SalesRules.MIN_AMOUNT_FOR_COUNT и проверяется методом isCounted. Сервис использует его в filter через ссылку SalesRules::isCounted, поэтому при смене порога правится одна строка. Один и тот же порог применяется и в topSales, и в countedByRegion, чтобы правило не расходилось между методами.
